# 设计取舍记录

这个项目有一条贯穿始终的约束：**核心库零第三方依赖**。本文逐条记录
每个"不用现成库"的决定、代价、以及为什么仍然值得。

判断标准只有一条：**在这个规模（几百到几千个数据点）下，自己写的代码
能不能被完全理解、完全测试、完全交付**。

---

## 1. 手写 JSON 解析器（不用 nlohmann/json）

| | nlohmann/json | 手写 |
|---|---|---|
| 单 TU 编译时间 | ~3 s | **0.4 s** |
| 依赖 | 单头文件但 2.5 万行 | ~500 行 |
| 错误处理 | 异常 | `JsonError` 带 `offset()`，可直接定位到字节 |

**代价**：不支持完整 JSON 标准——嵌套深度限 64，数字只认 double/int64。
**为什么仍然值得**：这条协议通道上的 JSON 是我们自己两边生成的，不是
互联网上的不可信输入。受限解析器反而把"对面发了什么"变成了可枚举的事。

关键实现细节：整数构造重载必须覆盖 `int/unsigned/long/unsigned long/
long long/unsigned long long` 全档宽度，否则 `int64_t`（Linux 上是
`long`）会触发歧义调用。这个坑是编译器抓出来的，写进这里防止复发。

## 2. 手写 OLS（不用 numpy / statsmodels）

**决策依据是发布体积**：

- 带部分主元的高斯消元解 (p+1)×(p+1) 正规方程：p ≤ 10 → 最大 11×11，40 行
- 引入 numpy：发布包从 几百 KB → **30 MB+**，并新增一个"用户机器装不上"
  的失败点

**代价**：没有向量化。几百个点的 AR 拟合在 1 ms 量级，无所谓。
**逃生门**：forecaster 层就是替换点——`@register` 一个新类即可接入重型
后端，调用方一行不改。这是**明确的工程取舍，不是能力上限**。

数值安全：滞后项高度相关 → 系数矩阵常接近奇异 → 部分主元是**必需品**
不是讲究。有专门测试覆盖奇异矩阵报错路径。

## 3. 手写测试框架（80 行，不用 GoogleTest）

GoogleTest 需要 `FetchContent` 拉网络依赖——离线环境直接构建失败。
80 行的 `FP_TEST / FP_CHECK / FP_CHECK_EQ / FP_CHECK_NEAR / FP_CHECK_THROWS`
覆盖了本项目全部需求，还顺带解决了两个真实问题：

- 用 `__LINE__` 拼标识符 + 名字作字符串，绕开 `##` 拼不出中文标识符的限制；
- `FP_CHECK_EQ` 用值拷贝而不是 `const auto&`，躲开
  `-Wdangling-reference` 误报。

## 4. 手写统计（不用 pandas）

`stats.py` 约 300 行，覆盖收益率/CAGR/年化波动/夏普/索提诺/最大回撤/
VaR/CVaR/偏度/峰度/自相关。三条包级约定：

1. 简单收益率（不是对数）——与业界报告口径一致；
2. 年化按 252 交易日；
3. **样本不足返回 None，绝不返回 0**——0 会被下游理解成"波动率真的是零"，
   那是个不报错的错误结论。

## 5. 预测区间的精确公式（不用 σ√h）

随机游走的 h 步误差方差是 `h·σ²`，很多实现把这个公式到处套。但 AR(p)
的正确公式是 `σ²·Σψ²j`（MA(∞) 表示的 ψ 权重递推）。φ 显著非零时，
σ√h **明显高估**不确定性——φ=0.8 的 AR(1) 在 h=10 处，真实标准差只有
√h 那个数的约 2/3。既然系数已经拟合出来了，用精确公式没有任何额外代价。

## 6. 技能分与方向命中率

- `skill = 1 - MSE_model / MSE_randomwalk`，随机游走是唯一严肃的对照
  （Meese–Rogoff, 1983）；
- 随机游走的方向命中率**固定记 50%**：它不携带方向信息，记 0% 会人为
  抬高所有模型的技能分；
- 技能分为负时，界面如实显示"不如随机游走"——**回测里最诚实的一句话**。

## 7. 合成数据源的波动率锚定

参数叫 `annual_vol` 就必须给出对应的波动率，否则是会实实在在误导使用者
的 bug。稳态方差满足：

```text
E[var] = ω / (1 - α·E[z²] - β)        E[z²] = (1-p) + p·scale² ≈ 1.26（跳变混合）
一根 K 线的对数收益 = drift + gap + shock
→ Var = E[var] · (E[z²] + gap_scale²)
两式联立解出 ω 和 var。
```

第一版只用了 `(1-α-β)` 当分母，`annual_vol=0.28` 实测 53.9%；第二版补了
跳变项还剩 37.6%；第三版补上跳空项才锚住（实测 29.7% / 31.2% / 30.5%）。
`test_annual_vol锚定_回归防线` 就是这段历史的永久防线。

## 8. Windows 句柄不进头文件

`Subprocess.h` 刻意不引入 `<windows.h>`——它会污染每个包含者的全局命名
空间（`min`/`max` 宏、几十个类型名）。句柄用 `std::intptr_t` 承载，
`.cpp` 里再做 `reinterpret_cast`。POSIX 侧则完全对称：头文件里同样
只有 `intptr_t`，平台差异被压缩在一个 `.cpp` 里。

## 9. Python 引擎只用标准库

三个理由：桌面包要连同引擎一起分发，多一个依赖多一份装环境失败率；
发行包体积；金融指标这个规模根本用不上向量化。
另外两个容易踩的实现坑，都有注释和退出码配套：

- stdout 连管道时默认 **8 KB 块缓冲** → 必须 `python3 -u` +
  `PYTHONUNBUFFERED=1` 双保险；
- `sys.stdin.buffer.read(n)` 会阻塞到读满 n 字节 → 必须用 `os.read`。

## 10. CSV 列名中英文别名

`日期/时间/trade_date` → `ts`，`收盘/收盘价/adj_close` → `close`，
`20240315` 紧凑格式（通达信/同花顺导出）……这不是"贴心功能"，而是
"数据从哪来"这个现实问题的直接回应：中文数据平台的导出格式就是那样。
`csv.Sniffer` 自动嗅探分隔符，处理制表符导出。
